## 1. 複雑機（complex）— 実装済み

### 機種: Piper PA-28R-201 Arrow III（教材モデル）、id `pa28r`
- 引込脚（既存の gear 基盤）＋定速プロペラ＋燃料噴射 200 hp。PA-28 系の幾何を Archer から流用し、
  重量 1,180 kg / MTOW 2,750 lb。複雑機の定義（引込脚・フラップ・定速プロペラ）を満たす。
- 性能の要点（ヘッドレス実測、steadyState / 自由飛行）:
  - Vy 90 kt 上昇率: 脚下げ 551 fpm / 脚上げ 879 fpm（脚の抗力がそのまま差になる）
  - 巡航 125 kt はスロットル 0.88 で到達。Vx 78 kt 脚下げ 675 fpm。
  - 定速プロペラの効率は etaK 0.55（固定ピッチ前提の 0.8 では Vy で 356 fpm しか出ず、
    定速プロペラの利点＝回転数を保つこと、を係数に反映した）。

### プロペラ制御モデル（physics.js、両サーフェス＝FLIGHT LAB と CADET の sorajima 複製）
- 状態 `s.prop`（レバー 0..1、1 = full forward）。ガバナー設定回転数 = propGov [1900, 2700] を補間。
- `rpmFor` に第6引数 `propLev` を追加し、`propCtrl` 機だけが新分岐を通る。他機種は従来式のまま
  （テストで Seminole の rpm 式が旧式と完全一致すること、Archer の Vy 上昇率が従来値 777 fpm と
  一致することを確認 ＝ 標準搭載時の物理ビット同一を維持）。
- ガバナーはマニホールド圧が足りる領域（スロットル約 1/4 以上）では設定回転数を保持し、
  アイドル付近でのみドループする（実機のガバナーの挙動）。
- 出力係数 propK = (gov/2700)^0.55 を既存の powK に乗算。MAN IN は同一スロットルでレバーを引くと
  最大 +1.5 inHg 上昇（スロットルプレート下流の流速低下）。
- 実測（thr 0.75、3,000 ft）: prop 1.0 → 2700 rpm / 21.7 inHg / propK 1.00、
  2400 設定 → 2400 rpm / 22.3 inHg / 0.94、1900 設定 → 1900 rpm / 23.2 inHg / 0.82。
  地上アイドル（レバー最小）609 rpm。
- 操作: `,` / `.` キーでレバーを動かす（アプリのコントロールストリップにも行を追加）。
  MFD の MAN IN 表示は単発 CS 機でも出るよう条件を拡張（双発は従来どおり）。

### レッスン（FLIGHT LAB 第6段階 s6「複雑機と教える側」）
- cx1: 離陸・脚上げ・巡航でプロペラを 2,400 rpm に設定（回転数低下と MAN IN 上昇を実測で採点）→ 戻す。
- cx2: GUMPS 着陸（脚の確認を含む着陸前点検 `cx_before_landing`、新規）。
- cx3: ゴーアラウンドの手順（プロペラ前進 ≤5 秒・フルパワー ≤3 秒・脚上げ・高度損失 ≤50 ft を時系列で採点）。
  セットアップでプロペラは巡航設定から始まる。
- チェックリスト `cx_before_takeoff` / `cx_before_landing` を school.js に追加
  （プロペラ FULL FORWARD は `s.prop >= 0.98` で判定）。
- 着陸の接地速度の幅: landingSteps に任意の `tdSpdTol`（既定 15 のまま）を追加し、cx2 のみ 20
  （重い複雑機はフレアが長く、接地までに速度が抜ける。進入自体の採点は ±5 kt のまま）。

## 2. 尾輪式 — 見送り（skipped）

判断根拠:
- 現行の地上操縦は `deriveAircraft` の中に前輪式前提で埋め込まれている
  （重心より後方の主脚＋操向可能な前輪という幾何と、離陸滑走のピッチ挙動）。
- 尾輪式の本質は「重心が主脚より後ろ」にあるための方向不安定性（グラウンドループ）、
  3点姿勢での離着陸、テールドラッガーのラダー権限の効き始めの遅れであり、
  フラグ 1 つのバリアントでは再現できない。フェイクの「尾輪っぽい何か」を出すのは
  この教材の品質基準（実測で裏付ける、できないものはできないと言う）に反する。
- 実装するなら必要なもの: 地上操縦の幾何パラメータ化（主脚位置・重心との前後関係・
  キャスター角）、地上ループの安定性モデル、3点／ウィール着陸の両方の採点基準、
  専用の REF（実機の訓練資料）との照合。工数は項目6全体と同程度を見込む。
- したがって今回は見送り。将来やる場合の開始点はこの節。

## 3. CFI モード — 試作 1 本（cf1）

- 形: FLIGHT LAB のレッスン 1 本。プレイヤーは右席の教官。
  1. ブリーフィング（会話選択肢）: 今日直す癖を言い当てる。
  2. 訓練生が飛ぶ 42 秒: `traineeFly` が PD 制御で `s.ovr`（既存の操縦上書き基盤）を駆動。
     シード（レッスンの seed）で決まる 1 種類のミスを時刻窓 14–34 秒に注入する
     （機首下げと速度への固視／スロットルを戻す／針路のずれ）。最大高度偏差を `L.cfiDev` に記録。
  3. 指摘（会話選択肢）: 実際に起きた偏差を引用して出題される（起きたことベース）。
  4. 介入: プレイヤー自身が 15 秒間、高度 ±60 ft・速度 ±6 kt・針路 ±10° を保持。
  5. 講評（会話選択肢）: 教官としての言葉の選び方。
- 設計上の限界（試作ゆえ）: 訓練生は 1 人・ミスは 3 種・介入は水平飛行のみ。
  操縦の取合せ（デュアルコントロールの力の奪い合い）、訓練生の上達曲線、
  教官としての評価軸（気づき・タイミング・言葉）は未実装。
- 本実装に進むなら: 訓練生プロファイル（癖の偏りと上達）、レッスン横断の記録、
  「言わずに直させる」採点（介入の早さではなく気づかせる質問の質）が必要。
  キャリア側は ch7 の課目として配線済み（卒業後のエンドースメントの一部として受講できる）。
