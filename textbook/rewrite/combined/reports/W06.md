## 2. したことと理由

### 2.1 `FL.jur` のデータ（`book-jur.js`）

DESIGN 3.4 の 1 項目の形をそのまま持たせました：`{ id, title, us, usSrc, usUrl, jp, jpArt, jpSrc, jpRefs, egov, w05, conf, boxes, gates, part7, safety, note }`。

- **米国の値**（`us`・`usSrc`・`usUrl`）：47 項目すべてを、2026-10-27 に一次資料の本文で確かめました（2.3）。米国の欄に〔要確認〕はありません。
- **日本の値**（`jp`・`jpArt`・`jpRefs`）：W05 の写し（`textbook/rewrite/sources/egov/`）と `jur-japan.json` の結果から書きました。条文は必ず法令名つき（「航空法施行規則第 178 条」）。`jpRefs` は写しの ref（`kokuho-kisoku:178`）で、テストが写しと照らします。W05 が見つけた DESIGN の 3 つの直し（`lights.ac` の衝突防止灯、`medical` の施行規則第 61 条の 2、`docs` の第 144 条と第 144 条の 2）は入っています。
- **e-Gov の版と確認日**（`egov` と `LAWS`）：航空法（令和 7 年 12 月 1 日施行）・航空法施行規則（令和 8 年 10 月 1 日施行）、どちらも 2026-10-27 確認。`time` だけは e-Gov の明治十九年勅令第五十一号（標準時）を足しました（W05 の写しの外。本文は e-Gov の API で読んだ）。囲みの下に「日本の法令は e-Gov 法令検索の版：…。2026-10-27 に確認。」と出ます。
- **確度**（`conf`）：W05 が写しで確かめた（confirmed）か直した（corrected）項目だけを「確認済み」（27 項目）にし、ほか（partial・not-egov・absent-in-egov の 20 項目）は全部「要確認」にしました。要確認の項目の日本の文には必ず〔要確認〕があり、囲みにそのまま出ます（テストで確かめる）。確認済みの項目でも、告示で決まる部分（`vmc.ad` の告示の空港、`nordo.ifr` の「国土交通大臣が定める時間」、`nordo.vfr` の 7600）はその所に〔要確認〕を書きました。
- **確かめられない数字は書いていません**：DESIGN の表にある日本の実地試験の「±50 ft」「200 ft」「±100 ft・±10°」、METAR の「G は平均より 10 kt 以上」「TEMPO 1 時間未満」は、日本の側では書かず〔要確認〕だけにしました。日本の METAR・TAF の書き方は、aviationweather.gov の RJTT・RJAA・RJCC の実際の METAR・TAF（2026-10-27）で見えたこと（毎正時と 30 分・9999・CAVOK・NOSIG・TEMPO・BECMG）だけを「例」として書き、決まりは〔要確認〕にしました。磁気偏差は NOAA の計算機（WMM-2025）で確かめた数（那覇 5.87°W〜稚内 10.54°W）です。
- **〔安全〕**：`fuel.vfr`・`alcohol`（DESIGN と同じ）。囲みの見た目には出さず、データとテストと安全レビューのための印です。
- **囲みの節・まとめ・第 7 部**（`boxes`・`gates`・`part7`）：DESIGN 3.4 の表と同じ（テストが DESIGN を読んで比べる）。
- **題**：DESIGN の題のまま。ただし用語の表 `FL.terms`（W04）に合わせて `ws.alert` を「ウィンドシャーの警報」、`lights.ac` を「航空機の灯火（航空灯）」（「航空灯」は通称、施行規則第 154 条の見出しは「航空機の灯火」）にしました。
- 文は平文だけ（HTML なし。描くときにエスケープ）。1 文 80 字以内に分けました（STYLE）。

### 2.2 部品（`book-core.js`）

| 部品 | 使い方 | 描くもの |
|---|---|---|
| `bk.jur(...ids)` | `bk.jur('alt.transition', 'alt.unit')`（配列も可） | 「日米の対照」の表。1 項目 1 行（`<tr class="bk-jur-row" data-jur="ID">`）：項目・米国（値＋出典）・日本（値＋条文）。日本の列（`td.jur-jp`）と、表の下の 1 行（`div.jur-jp.jur-foot`：e-Gov の版と確認日、第 7 部へのリンク）は日本の側 |
| `bk.us(x)` | x が `FL.jur` の ID なら データから（`data-jur`）、そうでなければ HTML をそのまま | 「米国では」の囲み。W07 が共通の節の 14 CFR の引用を入れるときは HTML で `bk.us('<p>…（14 CFR 91.17）。</p>')` |
| `bk.jp(x)` | 同じ | 「日本では」の囲み（版の行・第 7 部へのリンクつき） |
| `bk.same(x)` | 同じ | 「日本も同じ」の囲み |
| `FL.book.jurTable(章ID)` | 章末に | 「この章の日米の違い」：その章の節に実際に置かれた囲み（`data-jur`）の項目を、読む順に 1 回ずつ。囲みのない章は空文字 |
| `FL.book.jurAppendix()` | 付録のページに | 「日米対照表（47 項目）」：項目・米国・日本・確度・本の中で（いま本にある囲みの節・まとめ・第 7 部へのリンクだけ）。米国の資料の版と e-Gov の版の行 |

- **リンクは行き先があるときだけ**（決まり 6・13）：「→ 第 7 部で詳しく：（節の題）」は `FL.book.findSection(行き先)` が見つかったときだけ、日本の側（`jur-jp` の行・`bk.jp`・`bk.same`）にだけ描きます。見つからなければ文字も残しません。R1 には第 7 部もまとめの章もないので、1 つも描かれません（テストで確かめ、さらに仮の第 7 部の節とまとめの章を入れるとリンクが現れ、外すと消えることも確かめる）。節は描くとき（`h: () =>`）にリンクを調べるので、R4 で `book-7.js` が入れば囲みを書き直さずにリンクが出ます。
- `book-jur.js` を読まない製品では、ID の囲みは何も描きません（`bk.photo` と同じ）。読んでいるのに ID がない（打ち間違い）ときは例外を出します（空の囲みで隠れないように）。
- 描く文字はデータの文字だけです。数字もデータの数字だけ（テストで確かめる）。`FL.jur.textOf(item)` が、囲みが描く文字の全部を返します（検査の道具が使えるように：7 の 6）。
- スマホ（幅 700 px 以下）では表の行を上下に並べ、各欄の頭に「米国」「日本」と出します（CSS の `data-label`）。
