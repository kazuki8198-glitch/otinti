# CADET：パイロット訓練生シミュレーター

訓練生として訓練所で暮らし、歩いて、話して、点検して、乗って、飛ぶ。そういう一人称視点のゲームを作っています。計画は [`PLAN.md`](PLAN.md) にあります。

> 公開情報を基にした非公式のゲームです。航空会社・訓練所・人物はすべて架空です。実機訓練の代わりにはならず、航法にも使えません（NOT FOR NAVIGATION）。

## いまの段階：M1（歩く）

[`outputs/CADET.html`](outputs/CADET.html) をダブルクリックすると Chrome で開きます。インストールは要らず、オフラインでも動きます。WebGL2 が必要です。

「アカデミーへ」を押すと、アカデミーのブリーフィング室 1 に立っています。画面をクリックするとマウスで見回せます。扉を開けて廊下とロビーを通り、自動ドアから外に出て、駐機場で待っている今日の Archer まで歩いて行けます。ホワイトボードや掲示、模型、天気の画面などを E で調べると、FLIGHT LAB の課目と教科書から取った説明が出ます。話す（M2）と飛ぶ（M3）はこれから作ります。

### M1 で入ったもの

**歩く**
- 一人称で歩きます（歩き 1.45 m/s、Shift で走る 3.6 m/s）。少しずつ加速・減速するので、カメラではなく人が歩いている感じになります。
- 壁・家具・機体・木・標識にぶつかり、壁に沿って滑ります（体は半径 0.28 m・高さ 1.75 m の円柱）。どんなに速く動いても壁を抜けないように、細かく区切って動かしています（テスト 16 件）。
- 壁に斜めに当たったときは、壁に向かう分の速さだけを失い、壁に沿う分はそのまま残ります。30・60・144 fps のどれでも同じ速さで滑ります（テスト 3 件）。
- 足音は床で変わります（カーペット・塩ビの床・タイル・テラゾー・コンクリート・アスファルト・芝）。歩く速さに合わせた小さな頭の揺れは、設定で切れます。

**アカデミーの中（すべて架空）**
- ブリーフィング室 3 つ、訓練装置室（FTD）、2 階まで吹き抜けのロビー、運航管理、パイロットルーム、訓練生ラウンジ、教官室、計画室、廊下 2 本。お手洗いと 2 階は閉まっています。
- 窓は本物の透明なガラスで、外の駐機場が見えます。窓から入る日差しには影が付きます。
- 扉：開き戸（プレイヤーと反対側へ開く）、両開き、近づくと開く自動ドア（エプロン側と正面入口）、鍵のかかった扉。
  - 動いている扉にもぶつかります。
  - 扉の通り道に人が立っていると、扉はそこで止まります（人を押しのけて閉まりません）。60・144・240 fps のどれでも同じように止まります。
  - 途中で止まった扉は、描かれた扉の板の形どおりにぶつかります。
- 家具と掲示：机、椅子、長机、ソファ、本棚、ロッカー、訓練装置の席、ヘッドセット掛け、模型（FLIGHT LAB の機体の形を 1/13 に縮小）、ホワイトボード、画面、掲示板、訓練空域の地図（FLIGHT LAB のデータから描画）、時計、非常口の標示など。

**調べる**
- 視線の先にある物の名前が出て、E（または左クリック）で説明のカードが開きます。もう一度 E を押すか、その場を離れると閉じます。
- 調べられる物は 18 か所あります（今日の課目のホワイトボード、Archer と Seminole の模型、METAR、今日の予定、IMSAFE、TEM など）と、駐機場の今日の機体（覚える速度と外部点検の話）。

**画面と設定**
- 今いる場所の名前を左上に表示します（部屋・廊下・駐機場など）。
- Esc で一時停止します。再開、見学モードへの切り替え、設定（マウスの感度・上下反転・視野角・頭の揺れ・音量・画質・性能の表示）、操作の一覧、このゲームについて。設定はブラウザに保存されます。
- 音は Web Audio で作っています（音声ファイルはありません）。足音、扉、外の風・鳥・遠くの飛行機、建物の中の空調。

**建物の中の光**
- 空の光（IBL）は建物の中では弱めます（窓際は明るく、奥は暗く）。
- 天井の照明は、いまいる部屋の照明を本物の光源として点けます。
  - 部屋ごとに照明を最大 5 つのまとまりに分けます。そのため、部屋の中を歩いても光がちらつきません。
  - まとまりの分け方と高さは、床の明るさがなるべく均一になるものを起動時に選びます。廊下の明るさのむらは約 9 倍から約 2.5 倍に減りました。
  - 天井のパネルと同じく下向きの光なので、天井に光の斑点ができません。
  - 別の部屋に入ると、0.3 秒かけて切り替わります。
  - 壁の向こうの部屋の照明が漏れてくることはありません。
  - 屋外では光源を消すので、屋外の描画の負担になりません。
- 外から入ると目が慣れるように、明るさがゆっくり変わります。夜は天井の照明で部屋が明るくなります。

**描画の量を抑える工夫**
- 家具は部屋ごとにまとめ、見えない部屋は描きません。
- 単色の素材は 1 つのパレットにまとめて描画の呼び出しを減らしました。
- 家具の影は、プレイヤーのいる部屋と隣の部屋だけで計算します。
- 駐機中の機体は 1 機あたり 2 回の呼び出しで描きます。
- ブリーフィング室での描画は、1 フレームあたり 255 回・三角形 79 万（影を含む）です。

M0 で作った飛行場（滑走路・標示・灯火・標識・建物・植生・空・影・かすみなど）は、そのまま使っています。

### 操作

| キー | 歩くとき |
|---|---|
| クリック | 操作を始める（マウスで見回す） |
| W A S D | 歩く |
| Shift（押したまま） | 走る |
| E / 左クリック | 調べる・扉を開け閉めする・カードを閉じる |
| Esc | 一時停止（メニュー） |
| F | 計測の表示 |

見学モード（メニューから切り替え）では、壁を通り抜ける自由なカメラで飛行場の全体を見られます。

| キー | 見学モード |
|---|---|
| W A S D | 移動 |
| Shift | 速く |
| Space / C | 上へ / 下へ |
| G | 地面に立つ（目の高さ） |
| 1〜9・0 | 視点（駐機場・滑走路 36 の端・アカデミー・管制塔・ファイナル 2 km・上空・訓練空域・ブリーフィング室 1・ロビー・運航管理） |
| [ / ] | 時刻を戻す / 進める |
| P | パネルを隠す |

### URL のオプション

| オプション | 意味 |
|---|---|
| `?q=low` / `medium` / `high` / `ultra` | 画質 |
| `?t=19.3` | 時刻 |
| `?view=3` | 見学モードで、最初の視点を選ぶ |
| `?bench` | 10 の視点で、それぞれの描画時間を計測する |
| `?auto` | 開始画面を飛ばす |

## 開発

```
cd cadet
npm install          # three（0.186.1）と esbuild（0.28.2）。版は固定です
npm run build        # outputs/CADET.html を作る（--dev で読みやすい版）
npm test             # ビルドとテスト 7 本
npm run test:fast    # ブラウザを使わないテストだけ
node test/shots.mjs ultra 1280 720 9.6     # 各視点のスクリーンショットを test-output/ に保存
```

テストは 7 本です。

- `layout`：見た目と FLIGHT LAB の物理が一致すること
  - 舗装・湖・座標の変換を確かめます。
  - 2 万点をランダムに選び、舗装が一致するか照合します。
- `collide`：当たり判定（16 件）
  - 壁を抜けない、角や狭い扉でも止まらない、壁に沿って滑る、段差を越える、頭上の物の下をくぐる、光線の判定など。
  - 混み合った部屋でのランダムな歩行では、どの向きに動いても箱を飛び越えないことを確かめます。
- `doors`：扉（7 件）
  - 人に向かって閉まる扉が止まり、人を押さないこと（60・144・240 fps、片開きと両開き）。
  - 閉じた扉に体を付けていても、反対側へ開けられること。
  - 途中で止まった扉が、扉の板の形どおりにぶつかること。
- `walker`：歩き（3 件）
  - 壁に沿って滑る速さが、30・60・144 fps のどれでも理想の値（±3%）になること。
  - 正面から壁に当たると止まること。押し出されても走り出さないこと。
- `academy`：アカデミーの間取り
  - 部屋が重ならずに建物を埋めること。扉が、つなぐ 2 部屋の間の壁にあること。
  - 開く扉だけを通って、ブリーフィング室 1 から全部の部屋と外へ行けること。
  - 調べる物が部屋の中の見える高さにあること。駐機場までの道筋が扉を通っていること。
- `build`：1 つのファイルで、外部への参照がないこと
  - 中のスクリプトがすべて構文として正しいことを確かめます。
  - 大きさが 15 MB 以内であることを確かめます。
- `browser`：ヘッドレスの Chromium で動くこと
  - `file://` で開き、通信をすべて止めた状態で起動します。
  - ブリーフィング室 1 で歩くモードから始まることを確かめます。
  - 10 の視点（外 7、中 3）のそれぞれで、絵が描けていることと、描画回数・三角形の数が予算内に収まることを確かめます。
  - 実際の当たり判定で歩くテストをします。
    - 閉じた扉は通れません。
    - 扉を E で開けると、廊下・ロビー・自動ドアを通って今日の機体まで歩けます。
    - 機体を調べるとカードが出ます。
  - 扉の通り道に立って閉めようとすると、扉は止まり、プレイヤーは押されません。
  - ホワイトボードを調べるとカードが開き、離れると閉じます。鍵のかかった扉は開きません。
  - メニューと設定、夕暮れ、画質の切り替え、計測も確かめます。

FLIGHT LAB のソースは `../flight-lab/src` から直接読み込みます（コピーしません）。FLIGHT LAB 側のテストもあわせて実行してください。

```
cd ../flight-lab && npm test   # 48 件
```

## フォルダ

```
src/main.js            起動、歩くモードと見学モード、ゲームの 1 フレーム、テスト用の入口（window.__cadet）
src/world/             layout（配置・アカデミーの寸法。テスト対象）、ground、airfield、buildings、vegetation、landmarks、
                       academy（アカデミーの中と外）、doors（扉）、props（家具）、boards（ホワイトボードなどの文字）
src/content/           academy-spec（間取り・扉・家具・調べる物の文章。FLIGHT LAB の課目から作る）
src/player/            walker（一人称の歩き）、collide（当たり判定）、interact（視線の先の物を調べる）
src/render/            post（描画の流れ）、sky（太陽・空・影）、indoor（建物の中の光）、materials、textures、glsl
src/aircraft/          exterior（acmesh から作る機体と、その当たり判定）
src/audio/sfx.js       音（Web Audio で作る）
src/core/              quality（画質の段階と解像度の自動調整）、input（キーボードとマウス）
src/ui/                menu（一時停止）、settings（設定の保存）、spectator（見学用のカメラ）
assets/tex/            テクスチャ（CC0）。出典は assets/CREDITS.md
test/                  テストとスクリーンショットの道具
```
