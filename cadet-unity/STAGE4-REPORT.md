## 完了したこと（証跡つき）

### 1. 副操縦士フェーズの論理（Stage 1/2 で移植・検証済み、本ステージで棚卸し）
- キャリア側 FO 規則（入社・型式学科試験バンク q_jet/q_jperf/q_jsys、recordLeg、ラインチェック ≥12 セクター＋≥900 分、疲労 +26/レグ・連続勤務 ≤4 日・≥65 休養、機長名簿と評価）は Stage 1 の CadetCareer.cs に移植され、ボット全周同値（1,299/1,299 行・0ミスマッチ、2シード）に FO 境界プローブ（bot3）を含む。
- 737 機体（スプール遅れ・N1・逆推力・スポイラー）と型式課目 j1–j5 は Stage 2 で移植され、ボット同値 **147/147 課目**（49課目×3段階）に含まれる。j1 が最初のチェックリストで停止する挙動は JS 参照と同一（ジェット点検が参照する電気系スイッチはコックピット層の状態であり、FL 単体には無い——Stage 3 レポートの未達1と同根）。
- CFI 課目 cf1–cf3 も同じシラバス移植に含まれ、ボット同値済み。

### 2. ログブック（本ステージで新規移植＋同値）
- `flight/src/CadetLogbook.cs` — career/logbook.js 移植：entryFrom（tenths 丸め、dual/solo/xc/inst/me の配分、ソロ承認文、PA-44 の機種・登録切替）、introEntry（体験飛行の行）、cleanEntry（読戻し時の型清掃：文字列切詰・ID 正規表現・着陸回数クランプ等）、createLogbook 相当（add/totals/clear/replace、ILogStore 経由の永続化）。
- 同値：**4/4 行・0ミスマッチ**（作成した3エントリ全項目、totals、汚れたセーブの清掃結果、tenths テーブル）。ドライバ: flight/test/bot-log-js.mjs / BotLogCs.cs。
- 記録系の残り：Recorder / Analysis（プロファイル・GPX/CSV の基礎データ）は Stage 2 で移植済み。デブリーフ会話データは Stage 1 で JSON 化済みだが、**会話エンジン（dialog/engine.js のランナー）の C# 移植は未実施**のため、デブリーフの画面再生はできない。

## 未達（理由つき）

1. **FO フェーズの Unity 画面結線（羽田ラインフライングのシーン・PF/PM の実施画面）— 未実施。** 論理層は検証済みだが、Stage 3 のコックピット 3D 化（未達）と一体の作業であり、本ステージの範囲では論理の棚卸しとログブック移植までとした。
2. **音声（効果音・空間音響）— 未実施。** 原典は WebAudio の手続き合成（audio/sfx.js）で音声ファイル資産が存在しない。Unity 側は手続き AudioClip 合成＋3D AudioSource の新規実装が必要で、未着手。
3. **読み上げ TTS / 音声リードバック（ローカル Whisper）— 未実施。** 計画のみ（チェックリスト §8）。OS TTS 連携・STT の組み込みは行っていない。
4. **デバイス対応（ヨーク/ペダル/スロットル軸・複数デバイス識別）— 未実施。** 現状は縦切りのキーボード入力（Controls.cs）のみ。Unity Input System での軸割当・デバイス別マップ保存は未着手（チェックリスト §11）。
5. **AI 教官 — 未実施。** 会話データは JSON 化済みだが、tutor/session の C# 移植と HTTP クライアントは未着手（API キーは Secure Vault 経由が前提）。
