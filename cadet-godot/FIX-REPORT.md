# CADET Godot 版 v1.0.1 緊急修正レポート

対象: ユーザー実機報告（2026-11-02）「起動するといきなりフリー飛行の滑走路上で、
操作もできず何もできない」への対応。v1.0.0 の出荷物が「実際に遊べる状態」に
なっていなかったことを認め、実測で原因を特定して修正した記録。

## 1. 再現と直接原因（すべて実測）

再現テスト（本物の main シーンを通常モードで起動し、`Input.parse_input_event`
で本物のキー／マウスイベントだけを流す）で切り分けた結果、原因は入力経路の
故障ではなく、**入口と表示まわりの欠陥 4 件**だった。

### 原因 1: 入口そのものが無かった
起動するとタイトルもメニューもなく、開発用ハーネスのフリー飛行
（`bridge.start_free("rwy",...)`）に直行していた。画面の案内は右上の
14 px テキストのみで、「スロットルは R 長押し」「55 kt で S を引く」といった
初見必須の情報がどこにも出ていなかった。

### 原因 2: パーキングブレーキを解除するキーが存在しなかった
`parkBrake` アクション自体は移植されていたが、**どのキーにも割り当てが
なかった**（controls の KEY_ACTS に項目がなく、main のキー変換表にもない）。
HTML 原典では Shift+B（fly-mode.js）。エプロン開始は PARK セット＋位置
ピン留めでスポーンするため、この開始方法では永久に 1 mm も動けなかった。
実測: PARK 中はスロットル全開でも対地速度 max 0.04 kt。

### 原因 3: キャリア HUD が例外で一切表示されなかった
`_show_career()` が存在しないメソッド `career.ability(axis)` を呼んでおり、
表示のたびに例外が発生してパネルが空のままだった。同所に
`tired()`（bool を返す）を数値書式で出力する第 2 のバグも潜んでいた
（第 1 の例外に隠れて見えなかった）。キャリアボットのテストはこの表示
関数を通らないため未検出だった。

### 原因 4: キャリアの 1 日が永遠に終わらなかった
`_career_advance()` は F3 のたびに `schedule()` を読み直すが、schedule は
原典どおり「今日実施済みの予定を当日のプランに残す」仕様で done フラグを
返さない。実施済みを呼び出し側で記録していなかったため、ch1 では F3 の
たびに同じ座学と同じ地上ドリル（k1）が再実行され続け、実測では
day 2 から一切進まなかった（ドリル完了→再開の無限ループ）。

### 原因ではなかったもの
実入力経路（input_map.poll_keys → controls → bridge）そのものは故障して
いなかった。再現テストでは、実イベントの R 長押しでスロットル全開・
対地速度 79.1 kt・離陸・上昇まで到達できた。問題は、この経路が
**一度もエンドツーエンドで検証されないまま出荷された**ことにある
（スクリーンショット撮影は脚本キー `_shot_keys()` の自動操縦で、
157,347 件の同値テストはロジック同等性のみを証明していた）。

### スポーン状態と HTML 版との差
- 滑走路フリー飛行: エンジン始動済み（アイドル RPM 658 を実測）・
パーキングブレーキ解除済みでスポーン。従来どおりで変更なし。
- エプロン開始: PARK セットのまま（HTML 原典 flight.js の
startOnGround と同じ）。ただしガイドが解除手順を明示し、
Shift+B で即解除できるため詰まらない。
- タイトル画面自体は Godot 版の新設（HTML 版はブラウザ側 UI に
開始メニューがある）。レッスン選択をタイトルに統合した。

## 3. テスト証跡

### 新規受け入れテスト `test/run_play.gd`（恒常スイート化）
本物の入力イベントだけで以下を通す。**30 checks / 0 fails**、
スクリプトエラー 0、書式エラー 0。

1. コールドブート → タイトル表示、背後でシミュレーションが進まない
2. 「フリー飛行」を実マウスクリック → ガイド表示 → R 長押し（実イベント）で
スロットル全開、対地速度 max 79.1 kt、離陸・+30 ft 上昇、墜落なし
3. Esc → タイトル復帰
4. 「キャリアをはじめる」を実マウスクリック → intro 会話を Enter/数字キーで
最後まで進行
5. キャリアを F3／ドリル回答／試験回答（全問正解）で駆動し、107 ステップで
day 10 の初飛行（a1）に到達
6. 初飛行で実入力の操縦応答を確認（スロットル・ピッチ、墜落なし。a1 は
空中開始のため離陸ではなく操縦権威の確認）
7. PARK 回帰: エプロン開始で PARK オン → 全開でも gs max 0.04 kt →
Shift+B で解除 → gs 20.2 kt まで加速

スクリーンショット: `build/title-v101.png`（タイトル）、
`build/guide-v101.png`（ガイド表示中のコックピット）。

## 5. 残る既知の問題（正直な申告）

- FINAL-REPORT §6 の既知制限 14 件は不変（未署名 exe、音声認識 STT
未実装、AI 教官の自由質問は会話 UI 未接続、スロットル等のデバイス軸
一部未接続、HTML 版とセーブ互換なし、ほか）。
- 本修正の検証は VM 上（llvmpipe ソフトウェア描画）の自動テストまで。
Windows 実機での fps・操作感・見た目の最終判定は実機でしかできない。
- タイトルからレッスンを選ぶ場合の難易度は「導入」固定
（キャリア内の飛行は「基礎」）。レッスン一覧には地上ドリル k1–k6 は
含まれない（キャリア内で実施する設計のため）。
- 別セッションを跨いで同じ日を再開した場合、座学など当日の実施済み
項目が再履修扱いで表示されることがある（無害だが表示上の割り切り）。
- `test/run_play.gd` の所要時間は描画環境に大きく依存する
（この VM で約 7 分）。実 GPU 環境では大幅に短くなる見込み。
