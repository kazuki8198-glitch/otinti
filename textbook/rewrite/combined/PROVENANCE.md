## 2. 原本を変えずに残すやり方

- **触らない**：`flight-lab/kiso/` の下のファイルは、どの作業でも書き換えない・足さない・消さない（DESIGN 6.2 の決まり 12）。合本のための新しいファイルは原本のフォルダの外に置く：訂正依頼書 `textbook/rewrite/combined/ERRATA-FOR-WORD.md`、原本のページに重ねる訂正のデータ `flight-lab/src/kiso-errata.js`（W11）、台帳 `textbook/rewrite/combined/ledgers/`。
- **確かめる**：
  - 原本の 264 ファイルの sha256 を `textbook/rewrite/combined/tools/data/kiso-sha256.json` に記録してある（W01。git の HEAD と同じことを確かめた）。`tools/check-provenance.mjs` が毎回、git の差分ゼロと全ファイルの sha256 を照らす（5 章の基準 10）。
  - `ledgers/validate.mjs` も、台帳を調べるたびに `flight-lab/kiso/` の git の差分がないことを確かめる。
  - 製品のテストに入れる原本のハッシュのテストは W11 が作る（DESIGN 7.2）。
- **原本の入口と記録**：FLIGHT LAB のメニューの「基礎教材」の入口と、そのページの題・学習記録の行は、所有者が外すと決めるまで残す（判断 1 は未決。推奨は R5）。題の下に「第 3 版・原本（保存版）です」の 1 行を足し、安全と日本の法令の訂正（約 25 件）を原本の本文の外に重ねて出す（W11）。学習記録の `kisoRead`・`kisoQa` は原本のページの記録として残し、書き直した節の記録に読み替えない（DESIGN 6.4）。
- **写真のファイル**：合本で使う基礎教材の写真は、原本のファイルと**バイト一致**のまま使う（再エンコード・再縮小をしない。ハッシュで確かめる。DESIGN 4.2・基準 17）。原本のフォルダから読むだけで、コピーは製品の側に作る（W22）。

## 3. 合本で基礎教材をどう使うか

- **書き直す**：一字一句の転記はしない。教科書の文体と節の形で書き直す（DESIGN 1.1・4.2）。
- **由来を出す**：基礎教材から書いた節・囲みには、節のデータ `from`（基礎教材の節 ID の列）を付け、画面に「パイロット基礎教材（第 3 版）第 N 章 x 節をもとに改稿」と出す（DESIGN 3.2・基準 11）。全件の行き先は `ledgers/PROVENANCE.json` の由来表にあり、付録の「由来表」のページはこの表から作る。
- **出典**：基礎教材の節の参照番号のうち、実際に使った資料だけを、URL を開いて一次資料であることを確かめてから章の出典に足す（DESIGN 3.2）。
- **図**：描き直す図（約 55）は暗い板に描き直し、元の図番号と元の出典を記録する（DESIGN 4.2）。
- **写真**：使う 52 枚・条件つき 4 枚・使わない 29 枚（DESIGN 4.2）。クレジットを教科書の形 `{author, license, licenseUrl, source}` に移し、1 枚ずつ元のページで確かめる（W22）。CC BY-SA の写真は加工しない（原本の README の決まり 2 と同じ）。注記入りの写真のクレジットの「注記は本書で追加」「注記を加えて使用」は、合本の中では「**注記はパイロット基礎教材（第 3 版）で追加**」と書き換える（「本書」が合本を指して、注記を加えた人を偽らないように）。航空会社の写真（例 第 0 章の扉の全日空の 787）と、基礎教材の JAL の出典は合本に入れない（教科書の写真の決まりと CADET の架空の世界のため。原本には残る）。
- **本の名前**：「教科書」のまま。「パイロット基礎教材」「第 4 版」とは名乗らない（基礎教材の版は Word が正本で、その版のつながりを偽らないため。DESIGN 1・9 の判断 10 の推奨。判断 10 は未決）。
- **誤り**：基礎教材の既知の誤り・欠落 53 件は、合本の文で直す（`ledgers/ERRATA.json` の `K.*` の行）。原本は変えず、全部を `ERRATA-FOR-WORD.md` に書く。
