## 2. したことと理由

### 2.1 共通の作り

- **報告だけ**：どの検査も、数と問題の場所を出して終了コード 0。`--strict`（全部）か `--strict=style,figures`（その検査だけ）で、level が error の問題があると終了コード 1。DESIGN 5 章の「道具は W01 で報告だけで入れ、版ごとに止めるに切り替える」のため。問題の level は 4 つ：**error**（決まりに反する）・**warn**（たぶん誤り、または機械では確かめきれない）・**pending**（決まりが指す場所＝章・節・台帳がまだない）・**info**（数やメモ）。
- **製品と同じ本を読む**：`textbook/build.mjs` の `FL_MODULES`（TEXTBOOK が読む列＝本のいちばん広い列）を、W02 の `flight-lab/src/modules.mjs` があればその `modulePath()` で、新しい vm の中に順に読み込む。`quiz.js`・`quiz-jcab.js` はあれば足す。W02 が列を 1 つにしたので、W06 の `book-jur.js`・W09 の `book-0.js` などは、列に入れば道具も自動で読む。読み込まれていない `book-*.js`・`quiz*.js` があれば check-all の 1 行目に出す。
- **文字の検査は base64 を先に消す**：節の HTML は描いた直後に `data:image/webp;base64,…` を消してから全部の検査に渡す（`lib/book.mjs` の `sectionsOf`。章末の文字も同じ）。DESIGN 4.2 のとおり、基礎教材の写真 11 枚は base64 の中に偶然 `XXX`・`TBD` を含むため。
- **台帳がなくても止まらない**：`ledgers/*.json` は W03 が今書いているので、形をゆるく読む（行の配列／`rows` などの配列を持つ物／ID をキーにした物。項目の名前もいくつかの候補から拾う）。ないときは pending を 1 つ出し、全部を「まだ覆っていない」として数える。試すときは環境変数 `COMBINED_LEDGERS=<フォルダ>` で別のフォルダから読める。
- **設計書を予定表として読む**（`lib/design.mjs`）：DESIGN 3.3 の目次（289 節・48 章・各節の部と「範囲」と「元にするもの」の K 番号）、3.4 の 47 項目、4.2 の写真の使う／条件つき／使わない、3.2 の既知の概念の対を、その場で DESIGN.md から読む。台帳や `FL.jur` がまだない間は、これを予定として使い、「まだ本にない場所」を error でなく pending に分ける。読み取りの正しさは selftest で設計書自身の数（289・48・部ごとの 22/118/40/19/19/14/17/40・新しい節 135・47・52/4/29・13）と突き合わせた。

### 2.2 検査ごとの中身と決めたこと

- **chapters**：`flight-lab/test/flight.test.mjs` と `textbook/test/content.test.mjs` が章に求める条件をそのまま（各節 200 字超、用語 3、例・注意、理由つきの問 2 以上で選択肢 4、https の出典、課目・節・計算機のリンク、`{ch:}` の解決、TODO・TBD・PLACEHOLDER・XXX など、`<script>` なし、`<a>` は写真のクレジットだけ、描くたびに同じ HTML）。本全体の条件（注意書き、テストが求める語、radio1〜5 の位置、番号）も。下書きを登録の前に同じ物差しで測れるようにするため（決まり 5）。
- **form**：ねらいが最初、最初の図の前に説明がない、写真は最初の図より後、ここが大切は 2〜4 項目で各 60 字以内、思い出そうは 3 行以内でリンクつき、囲みの順（もっと深く → 判断の目 → ここを混同しない → ここが大切 → ここに注意 → 日米 → 思い出そう → 考えてみよう → シミュレータ）、シミュレータが最後。図のない節は info（CADET の教室の画面が空になる）。
- **data**：節 ID・章 ID の形（決まり 1）、部が PARTS にある、from の ID が基礎教材にある（DESIGN 3.3 で K から書く★の節に from がなければ warn）、deep・use・jcab・faa の形、知らない項目、DESIGN 3.3 と違う部（今は intro・sim が p0 の予定：W09 の addPart まで info）。
- **style**：です・ます（常体の文末）、体言止め、1 文の平均 40 字・最長 80 字（空白を除く字数）、留保の言い方（とは限りません・場合があります・ことがあります など 14 語）は「ここに注意」の外で 1 節 1 回まで、数字と単位の間の空白（STYLE）、FL.terms があれば用語の各章の初出の形。図・写真・表・ここが大切・式・計算機・出典・ボタン・見出し・考えてみようの問いの行・英語の文は外す。箇条書きの項目と「よくある間違い：…すること。」のような見出しつきの文は、本文の段落と分けて warn にした（段落の体言止め・常体だけが error）。
- **volume**：DESIGN 1.2 の数え方（SVG・タグ・空白を除く、実体参照は 1 字）。序部〜第 6 部の「まず読む節」（deep でない、gN と sim を除く）が 182,000 × 1.4 ＝ 254,800 字まで。
- **jurisdiction**：全節に scope。米国の規則の言葉（14 CFR・Part 61 など・91.155 などの条番号・AIM・FAR）は `us` の節、`bk-us`、`bk-jur` の米国の列 `jur-us`、または「米国」「アメリカ」と書いた文だけ。日本の規則の言葉（航空法（航空法規は除く）・施行規則・第 n 条・電波法・告示・通達）は `jp` の節、`bk-jp`・`bk-same`・`jur-jp` だけ。121.5 MHz のような周波数、「91.2 in」のような単位つきの数は除く。図の中の文字も調べる（場所に「（図）」）。出典の行・クレジット・リンクは外す。章末は warn。**scope のない節は、DESIGN 3.3 の「範囲」の列（共通・日米 → common、米国 → us、日本 → jp）で調べる**ので、W07 が直すべき所が今から見える。
- **chapter-refs**：「第 N 章」「第 24〜27 章」を、`{ch:}` を直す**前**の HTML・章末・学科テストで探し、直前（同じ文の 40 字以内）に出典の名前（PHAK・AFH・AWH・AIM・基礎教材・POH・CFR など）がなければ error。
- **claims**：節の文のうち、数字と単位・条番号・法令名・AC 番号を含むものを抜き出し、`<節ID>#<文の sha1 の 8 桁>` の ID を付けて CLAIMS.json の札（教材値・参考値・条文・推測/要確認）と照らす。`--out`（check-all では `--claims-out=`）で全件を JSON に書ける（事実確認役と W03 の台帳の種）。あわせて「教材値」があって「参考値」のない節を info（基準 6 の目安）。
- **ledgers**：ERRATA・RULINGS の全行が閉じている（直した場所／誤りでない理由）、直した人と別の確認役の署名、RULINGS の A は日米の項目 ID・C は用語を持つ。UNVERIFIED の数。
- **questions**：正解の番号が範囲内、同じ選択肢がない、ほかの選択肢を指す選択肢（すべて・どれも など）がない、理由に根拠（節へのリンクか出典の名前）、正解の位置の偏り（各 15〜35%）。**章末の確認問題は並べ替えずに出す**（FLIGHT LAB の pages.js・TEXTBOOK）ので warn、学科テストは表示のときに並べ替える（FLIGHT LAB の pages.js・CADET の school.js）ので info にした。今の 14 分野（CADET の筆記試験が読む）に日本の法令の言葉があれば error、`{ch:}` が CADET にない章（english・gN・第 7 部・intro・sim）を指せば error。記述問題 `written` の構造（開きタグのない `</b>`、次の問題群の案内文の混入）。基礎教材の原本の 376 問の崩れの数も参考に出す。
- **photos**：TEXTBOOK のテスト（`content.test.mjs` の写真のテスト）と同じ形のクレジット・WebP・1 枚 120 KB・メタデータなし・長い辺 1200 px・alt とキャプション・本文で使う・PHOTO-CREDITS.md に載る・`bk.photo('…')` の写真がある。加えて、写真ごとの加工の表示 `mod`、sha256（同じ写真が 2 回ない）、基礎教材の写真は原本の `kiso/photo/<ID>.webp` とバイト一致、DESIGN 4.2 で「使わない」写真（航空会社・計器の画面・ch00-photo7・画像のない ch12-photo3/4）がない、デコード後の合計が設計の予算 4.0 MiB・テストの 5 MiB 以内。W22 のために、使う予定の 56 枚の Commons のファイル名が `photoCreditsHtml` から取れるかも数える。`--out` でハッシュの一覧。
- **figures**（`textbook/rewrite/tools/figshot.mjs` のやり方を全図に広げた。figshot.mjs そのものは変えていない）：静的に viewBox の幅 360〜440、`role="img"` と aria-label＝キャプション、キャプションが「図：」で始まる、図いっぱいの白い四角がない、`&` がそのままでない、同じ章（TEXTBOOK の章のページ）で id が重ならない（本全体の重なりは info）。Chromium で、章ごとに 1 ページに全図を 390 px 幅で描き（figshot と同じ CSS）、文字の箱が viewBox の中・文字の箱の重なりなし・画面での最小の文字 10 px 以上（DESIGN の値。計算は font-size × 画面への拡大率）・SVG が単独の XML として読める。DESIGN の「既知のはみ出し」（fuelSystem など）は、この機械の字では収まっていて error にならなかったので、**字の幅の広いフォントで描いたときの見込み**（CJK 1 em・大文字と数字 0.66 em・その他 0.56 em）と、図の外へ出て切れる図形を warn にした。これで既知の 7 枚のうち 5 枚が引っかかる（下の 4）。`--no-browser` で静的な検査だけ。`--out`（check-all では `--figures-out=`）で問題のある図の PNG。
- **provenance**：原本 `flight-lab/kiso/` を git が変更と見ていないこと、264 ファイルの sha256 が `data/kiso-sha256.json` と同じこと（基準 10）。由来表が 393 節・376 問・161 図・85 写真を 1 回ずつ持ち、行き先か外した理由があること、節の from の ID とその行の行き先が合うこと（基準 11）。
- **maps**：JCAB-MAP・ACS-MAP の全行が節か「対象外（理由）」、名指しの節がある（DESIGN 3.3 にあって本にまだない節は pending）、節の jcab・faa が表の行を指す。
- **concepts**：太字の定義 `<b>語（English）</b>` が本の中で 1 回だけ。CONCEPTS.json（なければ DESIGN 3.2 の既知の 13 対）の住所の節があり、呼び戻す節に住所へのリンクを持つ「思い出そう」（`bk-recall`、3 行以内）がある。住所の節がまだないときは、リンクを求めない（決まり 13）。
- **jur**：47 項目（`FL.jur`、なければ DESIGN 3.4 の表）が、①囲みの節に `data-jur="<項目 ID>"` の囲み、②部のまとめの章、③第 7 部の節にあること。`FL.jur` があれば、囲みの中の数字がデータの米国・日本の値にあること。
- **calc**：例題を `{ id, sec, expr, vars, data, expect, tol, show }` の行にし、式（`lib/expr.mjs`：eval を使わない小さな計算器）で計算し直して本の値と比べ、`show` の文字がその節に出ているかも確かめる。`data` は `FL` の教材値（例 `physics.AIRCRAFT.0.v.y`）を式に入れる。見本 30 行（旋回の荷重倍数・失速速度の倍率・旋回率・旋回半径、密度高度、風と重量の離陸距離、VFR の燃料、雲底、規正値の誤差、突風の進入速度、推測航法、標準旋回のバンク、横風成分）。これは今の本の数字を本の式で計算し直したもので、新しい事実は書いていない。
- **path**：37 課目の `book` の節が課目の部と同じか前の部、後ろの部への `bk.see` は「予告」の札つきで全体 40 本まで、部の扉 `door` の思い出す節（6 以上・2 部以上前が 2 以上）、まとめの章の問いの 30% 以上が前の部。後ろの部の章を指す `{ch:}` も warn で数える。
