## 2. したことと理由

### 2.1 範囲の札と由来の行：`FL.book.secMarks(sec)`

- 引数は節（`{ id, scope, from, deep, … }`）か節 ID。返すのは `<div class="bk-marks">…</div>`、何もないときは空の文字列。FLIGHT LAB の `pages.js` と TEXTBOOK の `render.js` が**同じ HTML** を題の横に置く（`<div class="bk-head">` の中で題と並べる。`.bk-head .bk-marks { display: contents }` で札は題の右、由来の行は次の行）。CADET は呼ばない。
- 範囲の札（DESIGN 3.2）：`common` → 「共通」、`us` → 「米国の決まり」、`jp` → 「日本の決まり」、`mixed` → 「米国と日本の決まり」（3.3 の「日米を左右に」の節。DESIGN は mixed の札の文字を決めていないので、この言い方にした）。`scope` のない節（今は `sim` の 4 節と第 1〜6 部の 145 節）には札を出さない（推測で埋めない）。決まりにない `scope` は止まる（打ち間違いを隠さない。`bk.jur` と同じ考え）。
- 発展の札：`deep: true` の節に「発展」（題の横と、両製品の目次）。今の本に `deep` の節はない。`intro.marks` の「発展・折りたたみ」の行は `bk.deep` があると出る作りで、その行が言う「目次に『発展』の札が付きます」をこの単位で満たした。
- 由来の行：「パイロット基礎教材（第 3 版）第 5 章 14・16 節をもとに改稿」。原本の ID の形 `kisoNN.M`（節）・`kisoNN.cover`（章の扉）・`kisoNN.x1`（導入の節）・`kisoNN.qM`（問）から作る。並べ方：同じ章の節の番号は「・」、章の扉・導入の節・節・問の種類は「と」、章と章は「、」。例：`basics.rules` →「第 0 章 14 節、第 9 章 8 節、第 12 章 1 節をもとに改稿」、`intro.study` →「第 0 章 導入の節と扉をもとに改稿」、`intro.marks` →「第 0 章 扉をもとに改稿」。番号で終わるときは「をもとに」の前に空白（本の数字の書き方）。形の違う ID は止まる。ID が原本に本当にあるかは、FLIGHT LAB のテストが原本のデータ（`kiso-data.js`）と照らす。
- 序部の 18 節（`intro` 7・`basics` 9・`english` 2）は札が出て、うち 12 節は由来の行が出る（`intro.marks`・`intro.japan`・`intro.study`・`basics` の 9 節）。`intro.marks` の約束の表に「範囲の札」「由来の行」「発展」の 3 行が出るようになった（`book-1.js` の `marksDrawn`・`deepRow` の取り決めどおり）。

### 2.3 章末の説明してみよう：`FL.book.writtenHtml(ch)`

- 章のデータ `written` は `[[問, 答え], …]`（今の序部の形）か `[{ q, a, from }, …]`。配列の 3 つめに `from` を書いてもよい（`[問, 答え, ['kiso00.q1']]`）。問と答えは HTML（節の本文と同じ、信頼できる静的な中身）。`{ch:}` は直す。`from` は原本の問の ID（`kisoNN.qM`）だけ。形が違うと止まる。
- 置く場所：章の最後の節の章末、確認問題の後・「この章の日米の違い」と対応する課目の前（DESIGN 3.2「章末」の並び。用語の表が章末の最初の表であることは変わらない）。見出し「説明してみよう」、説明の 1 行「まず自分の言葉で説明してから（書き出すとなおよい）、答えを開いて確かめます。採点はしません。」、各問「問 N.」と「答えを見る」のボタン、答え（「答えの例」）は `hidden`。
- **答えをボタンで開く形にした理由**：TEXTBOOK のブラウザのテストは、全文のページの閉じた `<details>` の数を `COUNTS.details`（考えてみよう 126）と比べる。`<details>` にすると 22 増えて決め打ちの数が変わる（`textbook/test/load.mjs` はこの単位の持ち物でない）。基礎教材の原本のページの「解答と解説を見る」と同じボタンの形にそろえた。印刷では両製品の style.css が答えを開いてボタンを消す（`.bk-w-a[hidden] { display: block !important }`）。
- 記録のキー：「章ID.w番号」、番号は 0 から（`bookQuiz` の「章ID.番号」と同じ数え方。DESIGN 6.4 の「章ID.w番号」）。`data-w="basics.w0"` として HTML に入る。`written` は後ろに足すだけ（決まり 4）にすれば、キーは変わらない。
- FLIGHT LAB：答えを初めて開くと `bookWritten` に足して保存し、問に ✓、「答えを開いた問題 n / m」を数え直す。`from` のある問は由来の行（「パイロット基礎教材（第 3 版）第 9 章 問 3 をもとに改稿」）を出し、その原本の問を原本のページで開いていれば（`kisoQa`）「原本で開いた問題」と小さく示す（DESIGN 6.4。記録は読み替えない・書き換えない）。今の本の `written` には `from` がないので、この印はまだ出ない（6 の 2）。
- TEXTBOOK：開け閉めだけ（記録はしない。このページの記録は読んだ節と確認問題だけ）。検索は章末の文に問と答えを含めた。章末で見つかった語が隠れた答えの中なら、その答えを開く。
- CADET：`written` を読まない（`gameBook` は章の `id・n・title・part・sections` だけを持つ）。範囲の札と由来の行も本文の外なので、ゲームの本・教官の台詞・AI 教官の目次のどこにも出ない（テストで確かめた）。

### 2.4 学習記録 `bookWritten`（DESIGN 6.4、5 章の基準 26）

- `sanitizeProgress`：`bookWritten` は文字列の配列、形 `^[a-z0-9]{1,30}\.w[0-9]{1,3}$`（章 ID は英小文字と数字だけ：決まり 1）、重なりを除き、上限 1,000。ない・配列でない → 空。`kisoQa` とは別の項目で、互いに読み替えない。
- `mergeProgress`：両方を足して重なりを除く。書き出しは今までどおり `sanitizeProgress` を通るので `bookWritten` が入る。`version: 2` のまま。
- 古い書き出しの見本：`flight-lab/test/fixtures/progress-export-r1.json`（R1 の `exportJSON` で作った。`bookWritten` なし）が読めて、今までの項目（`read`・`bookQuiz`・`kisoRead`・`kisoQa`・`lessons`・記録）がそのまま、`bookWritten` は空になることをテストした。
